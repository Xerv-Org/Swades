**SWADES CODE RULES**

1. Untested code is rejected. No discussion. No exceptions. If it wasn’t run and verified, it does not enter the codebase.

2. You are fully responsible for every line you submit. AI-generated code is treated as your own work. “The model wrote it” is not an argument. If you cannot explain every line, do not submit it.

3. Any presence of `//TODO`, placeholders, unfinished logic, or hard-coded values that belong in config will result in immediate rejection. No warnings.

4. Code generated by Google models is treated as low-signal by default and faces higher scrutiny. Prefer stronger models or write it yourself. Slop is still slop regardless of the source.

5. Solve the problem with the absolute minimum number of lines and moving parts. Extra complexity is a defect. If a simpler solution exists, the current one is wrong.

6. Comments are restricted. Only non-obvious intent is allowed. Explanatory comments that restate the code will be deleted. Prefer self-documenting code.

7. Clarity is non-negotiable. Clever, dense, or “optimized” code that reduces readability is rejected. Complexity that cannot be justified is failure.

8. These rules are absolute. Violations are rejected without soft feedback or negotiation. Fix the code or do not submit.
